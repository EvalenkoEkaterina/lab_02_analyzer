# StreamStats — анализатор событий из CSV и JSONL

Лабораторная работа №2 по предмету "Программирование на Python"

## Что делает программа

StreamStats — консольная программа для анализа событий из файлов CSV и JSONL.

- **Чтение файлов** — обработка одного или нескольких файлов CSV и JSONL.
- **Потоковая обработка** — чтение файлов построчно без загрузки всех событий в память.
- **Статистика событий** — подсчёт общего количества событий и распределения по уровням и источникам.
- **Анализ ошибок** — определение топ-5 источников с наибольшим количеством ошибок.
- **Временной диапазон** — определение времени первого и последнего события.
- **Обработка некорректных записей** — возможность пропускать ошибочные записи с помощью `--skip-invalid`.
- **JSON-отчёт** — вывод результатов в терминал или сохранение в файл.

## Использование

### Анализ CSV

```bash
python -m streamstats analyze data/events.csv --format csv
```

Поддерживаются разделители:

- Запятая `,`
- Точка с запятой `;`
- Табуляция `\t`

CSV-файл должен содержать обязательные поля:

- `timestamp` — дата и время события
- `level` — уровень события
- `source` — источник события
- `message` — текст сообщения

Поддерживаемые уровни событий:

- `DEBUG`
- `INFO`
- `WARNING`
- `ERROR`
- `CRITICAL`

### Анализ JSONL

```bash
python -m streamstats analyze data/events.jsonl --format jsonl
```

Каждая строка JSONL-файла должна содержать отдельный JSON-объект с полями:

- `timestamp`
- `level`
- `source`
- `message`

Пример записи:

```json
{"timestamp": "2026-10-06T11:08:00Z", "level": "INFO", "source": "api", "message": "Started"}
```

### Анализ нескольких файлов

```bash
python -m streamstats analyze data/events1.csv data/events2.csv --format csv
```

Программа последовательно обрабатывает файлы и объединяет статистику всех событий в один отчёт.

Все входные файлы должны соответствовать формату, указанному через `--format`.

### Сохранение отчёта

```bash
python -m streamstats analyze data/events.csv --format csv --output report.json
```

Результат сохраняется в файл `report.json`.

Пример отчёта:

```json
{
    "skipped_events": 0,
    "total_events": 8,
    "levels": {
        "INFO": 2,
        "CRITICAL": 1,
        "ERROR": 3,
        "DEBUG": 1,
        "WARNING": 1
    },
    "sources": {
        "worker": 2,
        "auth": 2,
        "db": 2,
        "api": 1,
        "cache": 1
    },
    "top_errors": [
        {
            "source": "auth",
            "count": 2
        },
        {
            "source": "db",
            "count": 2
        }
    ],
    "first_timestamp": "2026-10-06T11:08:00+00:00",
    "last_timestamp": "2026-10-06T11:15:00+00:00"
}
```

Поля отчёта:

- `total_events` — количество корректных событий.
- `skipped_events` — количество пропущенных некорректных записей.
- `levels` — количество событий каждого уровня.
- `sources` — количество событий по источникам.
- `top_errors` — топ-5 источников по количеству событий уровней ERROR и CRITICAL.
- `first_timestamp` — время самого раннего события.
- `last_timestamp` — время самого позднего события.

При одинаковом количестве ошибок источники сортируются по алфавиту.

### Пропуск некорректных записей

```bash
python -m streamstats analyze data/events.csv --format csv --skip-invalid
```

По умолчанию программа прекращает обработку при обнаружении некорректной записи.

Параметр `--skip-invalid` позволяет пропускать ошибочные записи, выводить предупреждения через `logging.warning()` и учитывать их в поле `skipped_events`.

Для CSV обработка продолжается со следующей строки.

## Ошибки

CLI выводит сообщения об ошибках в `stderr` и завершается с кодом `2`.

Успешное выполнение завершается с кодом `0`.

Обрабатываются:

- неправильные или отсутствующие поля события (`InvalidEventError`)
- неверный формат даты и времени (`InvalidTimestampError`)
- неподдерживаемый формат входного файла (`UnsupportedFormatError`)
- неправильные аргументы командной строки (`CLIConfigError`)
- ошибки открытия, чтения и записи файлов (`OSError`)
- некорректный JSON в JSONL-файле (`InvalidEventError`)
- неправильный уровень события (`InvalidEventError`)

При обнаружении некорректной записи программа указывает имя файла и номер строки.

При использовании `--skip-invalid` предупреждения выводятся через `logging.warning()`.

Программа не допускает сохранение отчёта поверх входного файла.

- объединение нескольких файлов
- правильность подсчёта статистики
- сортировку топ-5 источников ошибок
- запуск программы через CLI
- сохранение JSON-отчёта
