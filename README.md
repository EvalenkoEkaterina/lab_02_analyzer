# StreamStats — анализатор событий из CSV и JSONL

Лабораторная работа №2 по дисциплине «Программирование на Python».

## Описание проекта

StreamStats — консольное приложение на Python для анализа событий, записанных в файлах CSV и JSONL.

Программа читает события, проверяет корректность данных, подсчитывает статистику и формирует отчёт в формате JSON.

Основная особенность проекта — потоковая обработка: файлы читаются построчно, без загрузки всех событий в оперативную память.

## Возможности

- Чтение файлов CSV и JSONL.
- Последовательная обработка одного или нескольких файлов.
- Потоковое чтение данных с использованием генераторов.
- Проверка корректности событий.
- Подсчёт общего количества событий.
- Подсчёт количества событий по уровням.
- Подсчёт количества событий по источникам.
- Определение пяти источников с наибольшим количеством ошибок.
- Определение времени первого и последнего события.
- Пропуск некорректных записей с помощью `--skip-invalid`.
- Вывод предупреждений об ошибках через `logging`.
- Вывод JSON-отчёта в терминал или сохранение в файл.
- Обработка ошибок командной строки и файлов.

## Форматы входных данных

### CSV

Программа обрабатывает CSV-файлы с обязательными колонками:

- `timestamp` — дата и время события.
- `level` — уровень события.
- `source` — источник события.
- `message` — текст сообщения.

Пример CSV-файла:

```csv
timestamp,level,source,message
2026-10-06T11:08:00Z,INFO,api,Application started
2026-10-06T11:09:00Z,ERROR,db,Database connection failed
2026-10-06T11:10:00Z,WARNING,auth,Invalid password
```

Поддерживаемые разделители:

- Запятая `,`.
- Точка с запятой `;`.
- Табуляция.

### JSONL

JSONL (JSON Lines) — формат, в котором каждая строка содержит отдельный JSON-объект.

Пример:

```jsonl
{"timestamp": "2026-10-06T11:08:00Z", "level": "INFO", "source": "api", "message": "Application started"}
{"timestamp": "2026-10-06T11:09:00Z", "level": "ERROR", "source": "db", "message": "Database connection failed"}
{"timestamp": "2026-10-06T11:10:00Z", "level": "WARNING", "source": "auth", "message": "Invalid password"}
```

Каждое событие должно содержать четыре обязательных поля:

- `timestamp`
- `level`
- `source`
- `message`

### Поддерживаемые уровни событий

Программа принимает следующие уровни:

- `DEBUG`
- `INFO`
- `WARNING`
- `ERROR`
- `CRITICAL`

Уровни `ERROR` и `CRITICAL` учитываются при составлении рейтинга источников ошибок.

## Использование программы

Все команды ниже выполняются из корневой папки проекта.

### Анализ CSV-файла

```bash
PYTHONPATH=src python -m streamstats analyze data/events_valid.csv --format csv
```

Программа читает CSV-файл и выводит статистику в терминал.

### Анализ JSONL-файла

```bash
PYTHONPATH=src python -m streamstats analyze data/events_valid.jsonl --format jsonl
```

Программа читает JSONL-файл и формирует отчёт.

Если входной файл имеет другое название, необходимо указать его фактический путь.

### Анализ нескольких файлов

```bash
PYTHONPATH=src python -m streamstats analyze data/events1.csv data/events2.csv --format csv
```

Программа последовательно обрабатывает указанные файлы и объединяет статистику.

Все входные файлы одного запуска должны соответствовать формату, указанному через `--format`.

### Сохранение отчёта

```bash
PYTHONPATH=src python -m streamstats analyze data/events_valid.csv --format csv --output report.json
```

Параметр `--output` указывает путь к файлу, в который будет сохранён JSON-отчёт.

Без `--output` результат выводится в терминал.

Программа запрещает сохранять отчёт поверх входного файла.

### Пропуск некорректных записей

```bash
PYTHONPATH=src python -m streamstats analyze data/events_valid.csv --format csv --skip-invalid
```

По умолчанию при обнаружении некорректной записи обработка останавливается с сообщением об ошибке.

При использовании `--skip-invalid` программа:

1. Обнаруживает некорректную запись.
2. Выводит предупреждение через `logging`.
3. Увеличивает счётчик `skipped_events`.
4. Продолжает обработку следующих строк.

Такой режим предусмотрен для CSV и JSONL.

### Справка

```bash
PYTHONPATH=src python -m streamstats --help
```

Команда выводит информацию об использовании программы и доступных параметрах.

## Параметры командной строки

| Параметр | Назначение |
|---|---|
| `analyze` | Запуск анализа событий |
| `--format csv` | Использовать формат CSV |
| `--format jsonl` | Использовать формат JSONL |
| `--output FILE` | Сохранить JSON-отчёт в файл |
| `--skip-invalid` | Пропускать некорректные записи |
| `--help` | Показать справку |

Для анализа необходимо указать хотя бы один входной файл и его формат.

## Формат отчёта

Результат работы программы представляет собой JSON-объект.

Пример:

```json
{
    "skipped_events": 0,
    "total_events": 20,
    "levels": {
        "INFO": 4,
        "CRITICAL": 4,
        "ERROR": 7,
        "DEBUG": 2,
        "WARNING": 3
    },
    "sources": {
        "worker": 3,
        "auth": 4,
        "db": 4,
        "api": 3,
        "cache": 2,
        "payments": 2,
        "search": 1,
        "frontend": 1
    },
    "top_errors": [
        {
            "source": "auth",
            "count": 4
        },
        {
            "source": "db",
            "count": 3
        },
        {
            "source": "payments",
            "count": 2
        },
        {
            "source": "api",
            "count": 1
        },
        {
            "source": "search",
            "count": 1
        }
    ],
    "first_timestamp": "2026-10-06T11:08:00+00:00",
    "last_timestamp": "2026-10-06T11:27:00+00:00"
}
```

### Описание полей

| Поле | Значение |
|---|---|
| `total_events` | Количество корректных событий |
| `skipped_events` | Количество пропущенных некорректных записей |
| `levels` | Количество событий каждого уровня |
| `sources` | Количество событий каждого источника |
| `top_errors` | Пять источников с наибольшим количеством ошибок |
| `first_timestamp` | Время самого раннего события |
| `last_timestamp` | Время самого позднего события |

Для `top_errors` учитываются события с уровнями `ERROR` и `CRITICAL`.

Сначала источники сортируются по убыванию количества ошибок.

Если количество ошибок одинаковое, применяется сортировка по названию источника в алфавитном порядке.

Для пустого файла программа возвращает нулевую статистику.

## Обработка ошибок

В проекте используются собственные классы исключений:

- `StreamStatsError` — базовый класс ошибок приложения.
- `InvalidEventError` — некорректное событие.
- `InvalidTimestampError` — неверная дата или время.
- `UnsupportedFormatError` — неподдерживаемый формат файла.
- `CLIConfigError` — ошибка аргументов командной строки.

Программа обрабатывает:

- Отсутствующие обязательные поля.
- Неверные значения полей.
- Недопустимые уровни событий.
- Ошибки формата даты и времени.
- Некорректный JSON.
- Ошибки чтения и записи файлов.
- Неверные параметры командной строки.

При ошибке программа сообщает имя файла и номер проблемной строки, если они известны.

Сообщения об ошибках выводятся в `stderr`.

При ошибке программа завершается с кодом `2`, при успешном выполнении — с кодом `0`.

## Потоковая обработка

Для чтения CSV и JSONL используются генераторы Python.

Генераторы позволяют передавать события по одному, не сохраняя весь файл в памяти.

Основные этапы работы:

1. Открытие входного файла.
2. Чтение очередной строки.
3. Проверка и преобразование события.
4. Передача события в анализатор.
5. Обновление статистики.
6. Переход к следующей строке.

Для подсчёта количества событий по уровням и источникам используется `collections.Counter`.

Обработка нескольких файлов выполняется последовательно.

В памяти сохраняются накопленные счётчики и необходимые значения статистики, а не полный список событий.
